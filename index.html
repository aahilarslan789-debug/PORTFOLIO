Project 1: Network Penetration Testing

Why I Built It

To understand the attack mechanics behind network exploitation. By executing an exploit myself, I learned how initial access and backdoors manifest in network traffic and logs, which is critical for writing effective SOC detection rules.

Objective

Perform network reconnaissance on a target host, identify running services, locate known vulnerabilities (CVE-2011-2523), and safely execute an exploit to achieve root access.

Tools Used

Kali Linux, Nmap, Metasploitable 2, Python (Custom Script), Wireshark.

What I Did

  • Ran targeted Nmap scans (-sV -sC) to enumerate open ports and identify the service version on port 21 (vsftpd 2.3.4).
  • Researched the target daemon and identified the CVE-2011-2523 backdoor vulnerability.
  • Reviewed the exploit logic and executed a Python script to trigger the backdoor mechanism by sending the :) string to the FTP service.
  • Intercepted the opened shell on bind port 6200 using Netcat and verified root access using whoami.

What I Learned & Outcome

I learned how malicious payloads interact with open ports, how high-numbered bind ports are opened during an exploit, and how to track unauthenticated root shell spawn attempts in network telemetry. Outcome: Successfully compromised the target machine, documented the attack chain, and detailed defensive mitigations.

Project 2: Cryptography & Password Security Lab

Why I Built It

Insecure password storage and unencrypted files lead directly to credential theft and data leaks. I built this project to practice using real security libraries to protect passwords and encrypt files at the application layer.

Objective

Build three Python programs on Kali Linux to stop plain-text password storage, encrypt sensitive files using AES-128, and automatically check password strength before saving credentials.

Tools Used

Kali Linux, Python 3, bcrypt library, cryptography library (AES-128 / Fernet), Linux CLI.

What I Did

  • Secure Authentication: Built a login and registration system using bcrypt to hash and salt passwords so credentials are never saved in plain text.
  • File Encryption: Created a tool using AES-128 encryption to safely encrypt and decrypt sensitive files on disk.
  • Password Analyzer: Developed a script that checks if a user's password is strong or weak, shows missing requirements, and gives security tips to fix it.

What I Learned & Outcome

I learned how password salting prevents rainbow table attacks, how AES encryption keeps files safe at rest, and how automated password checks reduce brute-force risks. Outcome: Built 3 working Python security scripts and created a full project report with terminal screenshots.

Project 3: Web Application Penetration Testing Lab

Manual security assessment of OWASP Top 10 vulnerabilities (SQLi, XSS, CSRF, File Uploads) on DVWA.

View GitHub Repository

Why I Built It

Web applications are often the main entry point for external attacks. I built this lab to practice identifying, manually exploiting, and documenting real-world web vulnerabilities using the OWASP Top 10 framework.

Objective

Perform a hands-on web penetration test against Damn Vulnerable Web Application (DVWA) to find critical security flaws, demonstrate proof-of-concept exploits, and provide fixes to secure the application.

Tools Used

Burp Suite Community Edition, Firefox ESR, OWASP Top 10 Framework, Linux CLI.

What I Did

  • Mapping & Interception: Configured Burp Suite proxy with Firefox ESR to intercept HTTP traffic and map out all target attack surfaces.
  • Exploitation: Manually tested and successfully exploited SQL Injection, Login Authentication Bypass, and Unrestricted File Upload vulnerabilities.
  • High-Risk Testing: Executed Cross-Site Scripting (XSS) payloads and verified Cross-Site Request Forgery (CSRF) flaws across target input fields.

What I Learned & Outcome

I learned how attackers manipulate HTTP requests, how unsanitized inputs lead to database compromise, and how to verify vulnerabilities without automated scanners. Outcome: Delivered a detailed penetration testing report featuring visual evidence and step-by-step remediation guidance.

Project 4: Vulnerability Assessment & Remediation Lab

Why I Built It

Automated vulnerability scanning is a core function in enterprise security operations. I built this lab to practice running automated network scans, prioritizing real-world security risks using CVSS scoring, and building structured remediation roadmaps for SOC teams.

Objective

Perform an automated vulnerability assessment against a Metasploitable2 host using Tenable Nessus, analyze scan telemetry to validate findings, and categorize remediation priorities based on threat severity.

Tools Used

Tenable Nessus Essentials, Metasploitable2 VM, CVSS v3.0 Framework, Linux CLI.

What I Did

  • Automated Scanning: Deployed Tenable Nessus to conduct a comprehensive network vulnerability scan.
  • Findings Analysis: Identified 73 total vulnerabilities (10 Critical, 7 High, 23 Medium, 9 Low).
  • Remediation Mapping: Structured a priority-driven patching schedule mapped to CVSS v3.0 scores (Critical: 0-24hrs, High: 1-7 days, Medium: 1-30 days).

What I Learned & Outcome

I learned how scanners collect host telemetry, how to separate critical exposures from low-risk findings, and how to translate raw CVSS metrics into actionable timelines. Outcome: Generated a complete assessment report with Nessus screenshots and a structured patching roadmap.
